# AI resource evidence

AI Resources is the Owner's read model over AccountCore, the harness inventory, Router 2.0, and Usage Analytics. Opening it only resolves local binary paths and reads stored or cached diagnostics. Installation, cached login, discovered model lists, configured model options, exact execution binding, provider identity, execution eligibility and permission, quota, and billing are separate. A found binary is not a login. A model list does not prove entitlement. Two local profiles are two stable records; without provider subjects, independent accounts remain Unknown.

## Owner workflow

In **Analytics → AI Resources**, choose the registered account, then **Record Owner-reported quota**. Choose an existing pool or create one with its native unit, category, account/model/group scope, and window. Enter the values shown by the provider, and optionally the observation time, reset time, source note, and evidence reference. Do not paste credentials or raw provider responses. The default freshness interval is 24 hours and can be changed or left blank; a reported reset can make a reading stale sooner. The latest manual reading and old readings are visible even when provider-verified quota is Unknown.

**Correct observation** appends a replacement in the same pool. The old observation stays in the journal and is marked Superseded. A correction cannot replace a provider observation, move an account's evidence, or branch a revision chain. A new pool and its first reading are written atomically. Migration 130 adds a unique index to the existing journal; fields are stored in its allowlisted JSON records. A display-name change does not move evidence. Archive retains history; profile backup includes the same SQLite rows. Cached login and live adapter grants are not restored by the journal.

Set a remaining percentage warning per pool. Warnings appear on AI Resources when a current reading meets the threshold. There is no polling or notification worker. Review the evidence source when acting on a warning. History is paginated. Changes are net changes within one comparable window: exact definition, source, native units, subject when available, compatible capacity, and the same reported reset or dated contract. No negative consumption is inferred after a reset or a correction. Group membership selects the same pool for multiple models. No account, model, window, or currency balances are summed.

## Automatic and manual sources

A registered read adapter must have an approved local binding before acquisition. Refresh is explicit and bearer protected. The coordinator rechecks authorization and account binding, validates scope, units and times, then writes an atomic batch. Authentication rejection, rate limiting, timeouts, and malformed responses preserve earlier observations. Only allowlisted fields enter the journal. Raw responses, authorization headers, and provider exception text do not.

The Cursor organization adapter implements the documented read-only pooled-usage operation, including the API's organization ID check. It needs an injected, separately authorized organization credential and a registered organization pool. Its contract dates are contract dates, not resets. It records native cents; the API does not give an unambiguous ISO currency on that response. If the reported budget is overdrawn, used and limit remain visible and no positive available amount is asserted. The adapter is not registered in production. A verified organization budget is not a Cursor CLI login, personal subscription quota, or proof of execution eligibility.

Codex app-server `account/rateLimits/read` windows keep `usedPercent`, duration, and reset time. A percentage is not a remaining-request count, and FO-PROVIDERS-RUNTIME01 does not redeem reset credits or perform a live read. The existing consented diagnostic remains observed and unverified because a stable exact provider-subject binding is unavailable. Settings → Harnesses now shows the same readiness facts for every supported harness: installed or missing, adapter version, authentication evidence, account binding, Unknown identity, Developer and Reviewer eligibility, sandbox compatibility, and the fact that authorized execution is not granted by opening the page. Anthropic and Cursor administrative usage APIs describe API or organization data rather than personal CLI quota. DeepSeek's balance response describes API credit in USD/CNY without a DSH subject. The official Claude, Cursor, Google, fx and DeepSeek interfaces can be used by the Owner to enter readings manually. A source catalogue documents which refresh actions are unavailable and why. See the [provider matrix and primary sources](../qa/fo-resources-complete01-results.md).

## Consumers

- **BACKLOG:** Candidate options use exact applicable pools. A comparable calculated API estimate can be expressed in minor units against same-currency API credit. Stale evidence, an elapsed reset, a reset before estimated completion, conflicting evidence or incompatible units leave capacity fit Unknown. Timing is conditional on starting now; the forecast is not a reservation. Subscription demand remains Unknown.
- **Actuals:** The existing ledger keeps run/task/agent/resource provenance, including the mode reported by the execution identity event. Historical rates are chosen as of run start. Reported billing, calculated API charges, subscription coverage, internal estimates and missing values stay separate. Ambiguous resumed Codex totals remain non-additive.
- **Router 2.0:** All applicable verified windows are considered, including explicit model group membership. A verified exhausted window denies admission even if another window has headroom. Strict admission needs fresh positive verified evidence; manual readings and configured warnings do not qualify. No pool balances are added. The six policy presets and exact selection are retained; any alternate resource still uses existing approval paths. Ranking can use comparable historical USD billing receipts; quality tier does not generate a dollar estimate.
- **Head of PM:** Resource questions use the same stored read models. Workspace scope can read the inventory; narrower scopes read accounts associated with in-scope project preferences or an in-scope approved mission, plus task/forecast data from that scope. Source labels, freshness, changes and Unknown fields are included as untrusted evidence. Source notes and evidence references are excluded from Head evidence. This creates no launch or provider grant.
