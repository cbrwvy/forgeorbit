## 1. Что уже хорошо (чтобы не сломать)

1. Основа для Glass уже есть (FO-001): токены `--glass-*`, классы `.glass-surface/.glass-bar/.glass-elevated/.surface-solid`, fallback для `prefers-reduced-transparency` и отсутствия `backdrop-filter`, блюр только на сайдбаре (`index.css:303-418`). Это правильная архитектурная идея — **дизайн-система развивает её, а не заменяет**.
2. Семантические токены `success/warning/info/danger` определены для обеих тем с учётом контраста (комментарии в `index.css:50-103`).
3. `prefers-reduced-motion` обработан глобально; `inert` на `<main>` в compact-режиме; роли `tablist/tab/tabpanel` и стрелочная навигация в Manager/Company/Portfolio.
4. Тема Auto/Dark/Light без мигания при загрузке.
5. Гейты Owner approval, 428/409-контракты, `data-testid`'ы — не визуальные, но любые правки UX обязаны их сохранять (см. §6).

## 2. Список проблем по приоритетам

Обозначения: **Наблюдение** — увидено в живом UI; **Код** — подтверждено исходником; **Метрика** — измерено.

### P0 — ломает использование

**P0-1. Карточки на «Обзоре» проекта обрезаны.** *Наблюдение + метрика + код.*
На 1440×900 строка статистики (`Tasks/Backlog/Ready…`) показывает только подписи, числа срезаны; секции «Окружение», «Документы проекта», «Команда», «Предложения назначений», «Последние задачи» усечены примерно вдвое (проба: `clientHeight/scrollHeight` = 36/66, 35/64, 98/180, 86/157, 79/144, 141/257), в «Окружении» видно обрезанное повторное слово «Environment». Причина: контейнер `flex min-h-0 flex-1 flex-col overflow-y-auto` (`WorkspaceOverview.tsx:43`) содержит дочерние `overflow-hidden` без `shrink-0` (`:58`, `:201` и др.); у flex-элемента с `overflow:hidden` авто-минимум высоты = 0, поэтому вместо прокрутки контейнера элементы сжимаются. Скриншот: `audit-02-project-overview-1440-dark.png`.
*Влияние:* главный экран проекта выглядит сломанным — это, вероятно, ядро впечатления «элементы расположены неровно».
*Исправление (UX02, ~1 строка на секцию):* `shrink-0` на дочерних секциях (или `grid` вместо `flex-col`). Требует регрессионного e2e на высоту карточек.

### P1 — серьёзно ухудшает навигацию и восприятие

**P1-1. Четыре независимые системы навигации.** *Наблюдение + код.*
(а) верхняя панель с 4 иконками без подписей (Git, Worktrees, Pipelines, Settings — `App.tsx:2526-2562`); (б) левый rail: 6 глобальных пунктов + проекты + «Add project / Clone repository»; (в) полоса вкладок проекта из 6 пунктов (Overview/Board/Estimates/Environment/Manager/Knowledge, `ProjectHeader.tsx`); (г) внутренние вкладки страниц: Manager (Chat | Autonomous Execution), Portfolio (Overview | Portfolio Manager + кнопка «Accounts & Resources»), Company (4 вкладки). «Knowledge» присутствует и в левом rail, и во вкладках проекта; «Portfolio Manager» живёт внутри Portfolio, а проектный менеджер — отдельной вкладкой проекта. Пользователь не может предсказать, где искать функцию.

**P1-2. Постоянная панель «New task» занимает 320 px (22 % окна 1440).** *Наблюдение + код (`NewTaskForm.tsx:717`, `w-80`).*
Рядом с ней — ещё левый rail 240 px; для контента остаётся ~880 px. Доска показывает 3–4 из 6 колонок с горизонтальной прокруткой, ряд фильтров переносится на вторую строку («Active only» уходит вниз). При этом в заголовке проекта есть ещё одна кнопка «New task» — **дублирование первичного действия** (`project-new-task` и «Run task»/«To backlog» в панели).

**P1-3. Task Queue, Task Plan и пакеты запуска спрятаны глубоко.** *Код (`grep`) + наблюдение.*
`TaskQueuePanel` монтируется только из `TaskPlanView` (`:125`), тот — только внутри `ProposalCard` (`:467`) за переключателем «Show plan», карточка — только в чате менеджера; пакеты (Execution batches) — на соседней вкладке «Autonomous Execution». Путь к очереди: проект → Manager → Chat → найти карточку предложения → «Show plan» → блок Queue. Для сценария «где управлять очередями и автономностью» это ≥5 кликов и зависит от того, что ИИ уже предложил план.

**P1-4. Task Details занимает 50 % окна и прячет разговор под четырьмя сворачиваемыми блоками.** *Наблюдение.*
Панель (`RunPanel`, `fixed right-0 … max-w-[90vw]`) открывается поверх доски; до начала разговора пользователь проходит строки «TASK DETAILS», «AI RESOURCE RECOMMENDATION», «EMPLOYEE EXECUTION», «TERMINAL» (все свёрнуты, но каждая — отдельная строка со своим стилем), под вводом — три ряда обвязки (Files/Folder, MCP·Skills·Plugins·Prompts, поле). В шапке — 4 иконки без видимых подписей; статус показан как сырой id харнесса `claude-code · review`. Скриншот не показывает дефектов контраста, но показывает иерархию «служебное выше содержательного».

**P1-5. Нет единой шкалы типографики и размеров контролов.** *Метрика + код.*
Computed-пробой по 5 экранам найдено 7 размеров шрифта (10/11/12/14/16/18/24 px); **10 и 11 px — 33 % всех текстовых узлов** (740 из 2 247). В коде 885 литералов `text-[10px]/[11px]` + 896 `text-xs`. Высоты интерактивных элементов: 10 разных значений между 20 и 40 px (20/23/24/26/27/28/32/36/38/40), пять из них отличаются на 1–3 px (23/24/26/27/28). Примитив `Button` задаёт только 32/36/40, но в коде 215 «сырых» `<button>` против 665 `<Button>` (24 % мимо примитива) и ад-хок высоты `h-6/h-7/h-8/h-9` (59/43/126/25 вхождений). Радиусы: 4/6/8/12 px + pill, причём `rounded-md` (403), `rounded-lg` (112), `rounded-xl` (111) смешаны на одном экране (карточки 12 px, кнопки 6 px, группа вкладок 8 px).

**P1-6. Glass в светлой теме практически не виден.** *Наблюдение (`audit-03-board-1440-light.png`).*
Фон `app-canvas` почти плоский (радиальные подсветки с альфой 0.06/0.035), поэтому блюру нечего размывать: сайдбар, шапка и колонки выглядят как обычные белые поверхности. В тёмной теме эффект тоже едва заметен. Т. е. «Liquid Glass» формально реализован, визуально — нет. Это ровно то, что отметил Owner.

**P1-7. Head of PM не имеет единой «двери».** *Код.*
Концепция «Head of Project Management» существует как сотрудник (`HeadFormDialog`, `HeadPortfolioBinding` на странице Company: «Not appointed», «Portfolio Manager Binding: Unbound»), глобальный чат — как вкладка «Portfolio Manager» внутри Portfolio, проектный — вкладка «Manager» проекта. Из любого другого места приложения (доска, Task Details) обратиться к главному агенту нельзя. Это расходится с замыслом «центральная роль».

### P2 — раздражает, но не блокирует

- **P2-1. Hover/active/focus разнородны.** Есть `.glass-nav-item` (hover через `--hover`), но кнопки используют `hover:bg-accent`, шаблоны диалогов — свои. Фокус: глобальное правило `:where(...):focus-visible` + `focus-visible:ring-2 ring-offset-2` в `Button` — два разных кольца. *Код.*
- **P2-2. Портфель: плотный текст без иерархии.** Карточки проекта содержат абсолютные пути, переносимые посреди слова (`…/proj-Helios-` / `Docs`), 4–5 строк «Description unknown / Stack: None detected / Signals: unknown · … / Runs 0 · paused batches 0 · harnesses none» одним кеглем, 5 кнопок и чекбокс «Exclude in what-if» + «Hypothetical priority» в каждой карточке. Заголовок страницы: три «кнопкоподобных» элемента разной формы («Accounts & Resources» — кнопка, «Overview» — выбранная вкладка, «Portfolio Manager» — невыбранная вкладка), «Refresh» упал на вторую строку. *Наблюдение.*
- **P2-3. Состояние Manager «Confirm the agent to start» (жёлтое) и пустой лог** не объясняют следующий шаг: кнопка Send серая, причина — в мелком тексте под полем. *Наблюдение.*
- **P2-4. Компактный режим (≤1000 px):** два столбца-иконки подряд (левый rail + свёрнутая New task с вертикальной надписью), их переключатели расположены на общей границе. Доска при этом получает ширину, но навигация превращается в набор безымянных иконок. *Наблюдение (`audit-03-board-1000-dark.png`).*
- **P2-5. Пустые состояния** («Pending», «Create a batch…», «No batches yet for this project») — текст без иллюстрации и без главной кнопки на том же месте; «Execution batches» показывает кнопку «New batch», но справа отдельная карточка с описанием. *Наблюдение.*
- **P2-6. Settings → General** — длинный список из 8+ переключателей в одной прокрутке без группировки (Appearance / Agents / System). *Наблюдение.*
- **P2-7. Журнал активности** показан кнопкой на странице проекта в одном ряду с блоком статистики, не как раздел. *Наблюдение.*

### P3 — полировка

- Иконки Lucide разных размеров (`size-3`, `size-3.5`, `size-4`) без правила.
- Двойные заголовки (название проекта в шапке + «Overview» вкладка + заголовок секции).
- Подпись «Unassigned» (кластер) под путём проекта выглядит как ошибка, а не как «нет кластера».

## 3. Дублирование и «слишком длинные» сценарии

| Сценарий | Сейчас | Предложение |
|---|---|---|
| Поставить задачу | панель New task (всегда открыта) **или** кнопка в шапке проекта **или** из Manager (`Execute a task` picker) | одна глобальная команда `＋ Новая задача` (⌘N) + контекст проекта по умолчанию |
| Подтвердить запуск | RunPanel: «Run task»; Manager: «Approve & Execute»; Batch: Approve → отдельный Start | единая «карточка подтверждения» (один компонент, те же гейты) |

| Что требует решения | `Needs attention` (Portfolio) + оранжевые кнопки Answer/Review на карточках + toasts | единый «Нужно вам» (inbox) с бейджем в навигации |
| Очередь | Proposal → Show plan → Queue | вкладка проекта «План и очередь» |

## 4. Гипотезы, которые НЕ подтвердились / не проверены

- Контраст текста: в живых скриншотах нет визуально нечитаемых мест; численная проверка существующего приложения не проводилась (контраст измерен только у прототипа). Токены `index.css` рассчитывались на AA (комментарии в файле) — оставлено без изменений.
- Производительность blur на WKWebView/Apple Silicon не измерялась (нет доступа к нативному окну в этом задании); см. риск R3 в `fo-ux01-design-system.md`.
- Pipelines-канвас, Estimates, Environment, Knowledge — не оценивались на реальных данных.

## 5. Корневые причины (сводка)

1. **Нет слоя дизайн-токенов выше цвета:** отсутствуют токены типографики, высот, радиусов, отступов — каждый компонент выбирает значения сам (P1-5).
2. **Информационная архитектура выросла по принципу «ещё одна вкладка»** по мере FO-001…FO-ORCH09 (P1-1, P1-3, P1-7).
3. **Постоянные панели вместо вызываемых** (New task, RunPanel) съедают рабочую область (P1-2, P1-4).
4. **Glass задан токенами, но фон не даёт материала для блюра** (P1-6).
5. **Неверный flex-контракт на странице обзора** (P0-1).

## 6. Что нельзя ломать при редизайне (контракты и регрессии)

- `data-testid` в `e2e/` (104 spec-файла в `e2e/`, из них 50 ссылаются на `project-page-*`, `workspace-*`, `project-new-task`): переносить вкладки можно только вместе с обновлением спеков либо сохраняя testid.
- Owner approval gates: Approve proposal, «Подтвердить и запустить», Approve batch/Start, Autonomy grant, Employee run review — менять только оформление.
- Модель компактного режима (`inert` на `<main>`, `compactPanel`), `Escape`-координация через `data-popover-open` (CLAUDE.md, пункты 11/RunPanel).
- Единственный экземпляр `RunPanel` без `key`; `fixed`-портал контекст-меню (transform-предок).
- Boot-канал темы (`window.__AGETOR.theme` + hash) — не трогать.
- Тема по умолчанию Auto; шкала шрифта пользователя (`font-size-provider`) — токены размеров должны быть `rem`-совместимыми.
